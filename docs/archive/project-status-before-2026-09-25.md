- محل فیزیکی دستگاه با رویداد قابل پیگیری و مجوز پذیرش/تعمیر ثبت می‌شود.
- خروج بدون تعمیر با دلیل، هویت تحویل‌گیرنده، تأیید کاربر و کنترل موجودی/مبالغ اضافه شد.
- چاپ مجدد رسید و برچسب از داخل پرونده اضافه شد.
- TypeScript و Build موفق؛ ۹۰ آزمون موجود پاس شدند. آزمون عملی چاپ و گردش کامل و بررسی دیداری هنوز انجام نشده‌اند.

- دفترچه راهنمای فارسی و PDF کاربر الزامی است: برای هر صفحه راهنمای علامت سؤال، روش کار گام‌به‌گام، تصویر واقعی رابط و خطاهای رایج تهیه شود. فصل خدمات باید پذیرش، استعلام و بارکدخوان، تصمیم گارانتی، برآورد، تخصیص تعمیرکار، قطعه و اصلاح آن، آزمون نهایی، تعویض دستگاه، چاپ، پیامک، تحویل، خروج بدون تعمیر، محل فیزیکی و رهگیری مشتری را پوشش دهد.
- پذیرش دستگاه از میز خدمات به مسیر مستقل `/service/reception` منتقل شد. صفحه جدید سه گام واقعیِ استعلام سریال، بررسی فروش/گارانتی و ثبت پذیرش را نشان می‌دهد، منطق API قبلی را بدون نسخه موازی استفاده می‌کند و در موبایل به چیدمان تک‌ستونه تبدیل می‌شود. TypeScript و Build موفق‌اند؛ بازبینی دیداری کاربر باقی مانده است.
- ظاهر منوی کناری خدمات با منوی آبی حسابداری یکپارچه شد: قاب و سایهٔ جداگانهٔ hover برای هر آیتم حذف و رنگ بخش نیز هم‌سبک حسابداری شد؛ ساختار و دسترسی‌های منوی خدمات تغییر نکرده‌اند.
- بارکدخوان مشترک براساس نوع دستگاه عمل می‌کند: گوشی و تبلت برنامه دوربین را برای عکس‌گرفتن باز می‌کنند و تصویر به‌صورت محلی روی HTTP خوانده می‌شود؛ رایانه ورودی اسکنر USB/Bluetooth دارد و دستگاه ناشناخته فقط ورود دستی نشان می‌دهد. موتور محلی خواندن بارکد خطی و QR افزوده شد و هیچ تصویر بارکد به سرویس بیرونی ارسال نمی‌شود.

کل پروژه دوباره از ابتدا خوانده نشود. ابتدا همین فایل و سپس فقط ماژول مرحله بعد و وابستگی مستقیم آن بررسی شود:

1. مرحله بعدی اصلی: صورتحساب رسمی مالیاتی، ارزش افزوده و زیرساخت غیرفعالِ قابل اتصال به سامانه مودیان؛ ابتدا فقط فایل‌ها و منطق فروش/مالیات مرتبط بررسی شوند.
2. سپس صورتحساب رسمی، مالیات و ارزش افزوده و زیرساخت غیرفعالِ قابل اتصال به سامانه مودیان تکمیل شود.
3. گردش کامل حسابداری، خرید، فروش و خدمات با داده عملیاتی واقعی به‌صورت تعاملی آزمایش شود.
4. اتصال پیامک برآورد، آماده‌تحویل و تحویل فقط پس از تأیید صریح کاربر درباره ارسال شماره مشتری، مبلغ و کد پیگیری انجام شود.
5. آزمون دیداری موبایل و دسکتاپ پس از رفع محدودیت ACL اتصال مرورگر ویندوز انجام شود؛ بررسی HTTP محلی و LAN موفق است.
